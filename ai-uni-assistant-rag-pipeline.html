Full RAG Pipeline – Overview

offline-ready · step-by-step
  • Offline indexing (prep): Documents → Ingest → Chunk → Embed → Index into Vector DB.
  • Runtime (query-time): User query → Retrieve (Top-K) → Rerank (optional) → Augment (prompt) → Generate (LLM) with grounded context.
  • This is the standard RAG pipeline used by AI assistants (retrieval before generation to reduce hallucinations).
Key idea: RAG = retrieve relevant knowledge first, then augment the prompt, then generate an answer grounded in that knowledge.
2

1. Document Ingestion

load raw sources
  • Ingestion pulls raw content from multiple sources (PDF, Markdown, HTML/Web, TXT).
  • The loader extracts and cleans the text (removes noise, preserves structure where possible).
  • Output: normalized documents, ready to be split into chunks.
3

2. Chunking (Text Splitting)

split for retrieval · preserve context
  • Chunking splits long documents into smaller, retrievable pieces (token/character-based with overlap).
  • Chunk overlap preserves sentence/paragraph continuity so retrieval doesn't cut critical context.
  • Each chunk keeps metadata (source file, page/section) to support citations later.
4

3. Embeddings (Vectorization)

text → semantic vectors
  • Each chunk is passed to an embedding model to convert text into a numerical vector.
  • Vectors capture semantic similarity (similar meanings cluster together in vector space).
  • We store chunk + vector + metadata together for indexing & citations.
5

4. Indexing – Vector Database

store for fast similarity search
  • Embeddings are indexed in a Vector DB for efficient similarity search at query time.
  • Uses Approximate Nearest Neighbor (ANN) (e.g. HNSW) to retrieve relevant chunks quickly.
  • This becomes your external knowledge base (separate from the LLM's trained data).
6

5. Query & Retrieval

user question → relevant chunks (Top-K)
  • At runtime, the user query is embedded with the same embedding model.
  • We run semantic similarity search (cosine similarity) against the Vector DB.
  • Returns Top-K most relevant chunks (with scores + source metadata) to ground the answer.
7

6. Reranking (Optional but Recommended)

re-score for precision
  • Reranking re-orders Top-K using a cross-encoder (scores query+chunk together, not separately).
  • Improves precision: pushes the most relevant chunks to the top, trims less useful ones.
  • Gives the LLM a smaller, higher-quality context (less noise, better grounded answers).
Note: Optional stage — shown as dashed/branch in classic RAG; many production RAG pipelines include reranking.
8

7. Augmentation – Prompt Construction

grounded context → structured prompt
  • We augment the user query by injecting the retrieved (reranked) context into a prompt template.
  • Instructions often include: "Answer strictly from the provided context. Cite sources. If unknown, say so."
  • This is the key RAG step: ground the generation in retrieved knowledge, not just training data.
9

8. Generation (LLM) → Answer

grounded response + citations
  • The LLM generates a response using the augmented (grounded) prompt — constrained to the retrieved context.
  • Result: a grounded answer with reduced hallucinations, often with source citations (traceable back to original chunks/docs).
  • Full RAG complete: Retrieve → Augment → Generate. The answer is based on your knowledge base, not only the LLM's trained data.
AI Uni Assistant RAG: Prep (Ingest–Chunk–Embed–Index) + Runtime (Query–Retrieve–Rerank–Augment–Generate) = grounded, citation-aware retrieval-augmented generation.
