Chatbot → RAG → Agentic Chatbot → Agentic RAG → Agent

A playable animated schema. Watch the glowing dot: it shows how information flows — and whether the system can loop, decide and act.

1

Plain Chatbot (pure LLM)

no tools · no retrieval · one shot
  • You type a question → it goes straight to the LLM.
  • The LLM replies purely from what it learned during training — frozen weights, no lookup, no API.
  • Prompt in → text out. One shot: it cannot check anything, retry, or decide its next step.
That's a chatbot. Chat-shaped UI, zero autonomy — even if it sounds agentic.
2

RAG (Retrieval-Augmented Generation)

retrieve → generate · still linear
  • Before answering, the system fetches relevant chunks from your own documents (vector DB).
  • Chunks are stuffed into the prompt → the LLM answers with grounded context + citations instead of hallucinating.
  • But the flow is a fixed one-way pipeline: it retrieves once, never checks quality, never re-plans.
A smarter chatbot, still not an agent. It has one tool hard-wired in a fixed order — zero decisions of its own.
3

Agentic Chatbot

uses tools · but stays on rails
  • The LLM can now call predefined tools — weather API, calculator, search — to actually do things.
  • So it looks agentic… but it's usually one request → one tool → one reply, from a fixed menu.
  • It reacts to your message. It never pursues a long-running goal, never builds a plan, never retries.
Tool use ≠ agent. This is a chatbot with tools — narrow scope, shallow loop, no autonomy. (Most "AI agents" in marketing are this.)
4

Agentic RAG

RAG + a reasoning loop
  • Now the LLM controls retrieval instead of being wired to it: it decides whether to search and what to search.
  • It grades the results — if the chunks are weak it rewrites the query and retrieves again, maybe hops to another source.
  • Retrieval stopped being a fixed pipe and became a tool the agent chooses, in a loop, until it's confident.
RAG that thinks before it retrieves. Classic RAG = function call. Agentic RAG = loop with judgment. Same ingredients, different control flow.
5

Agent

goal → plan → act → observe → repeat
  • You hand it a goal, not a command. It breaks it into steps and picks its own tools (browser, code, DB, files…).
  • It acts → observes the real result → updates the plan, including recovering from failures.
  • And it keeps looping until the goal is met (or it asks you). No fixed pipeline to fall out of.
The real thing = loop + tools + goal + autonomy. RAG can live inside it as one tool; the chatbot is just its most restricted cousin.
